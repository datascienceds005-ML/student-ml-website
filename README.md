# 🎓 AI Student Performance Prediction System

An end-to-end Machine Learning web application that predicts a student's **final exam score (0–100)** from their study habits and background, using a **Linear Regression** model and an interactive **Streamlit** interface.

Built as an internship project at **PaulTech Software Services Pvt. Ltd., Sakchi, Jamshedpur** by **Suraj Kumar** (B.Tech Data Science, Srinath University).

## 📌 Project Overview

Schools collect a lot of data about students — attendance, study habits, past scores — but rarely use it to help students *before* the final exam. This project turns that data into an early, easy-to-understand estimate:

- You enter a student's habits and background.
- The app predicts their likely **final exam score**.
- It also shows a **performance band** (Excellent / Good / Average / Needs Improvement) and a progress bar.

**Why Linear Regression?** It is simple, fast, and *explainable* — every prediction is a weighted combination of the inputs, so the reasoning can be understood by students, parents, and teachers rather than hidden inside a black box.

---

## ⚠️ Important Limitations — Please Read

This app is a **fixed-schema demonstration system**, not a general-purpose prediction tool.

- **The pre-trained model only works for this specific dataset structure.** The saved model (`models/linear_regression_model.pkl`) was trained on exactly the columns listed in [What Each Saved Artifact Does](#-what-each-saved-artifact-does), in a fixed order, with a fixed scaling. It has no knowledge of any other data.
- **It cannot accept arbitrary or random external CSV files.** The app has no file-upload feature, and a CSV with different columns, different units, or a different target would give meaningless results — or fail outright. To use different data, you must **retrain** the model (see the [Retraining Guide](#-using-a-new-dataset-retraining-guide)).
- **The included dataset is synthetic.** `data/student_data.csv` was generated by `data/generate_dataset.py` to mimic realistic student data. The reported accuracy demonstrates that the *pipeline works*; it is **not** a guarantee of accuracy on real students.
- **Inputs are limited to predefined ranges.** The sliders only allow values the model was trained on. Predictions are clipped to the valid 0–100 range.
- **Linear model assumptions.** Linear Regression assumes each factor's effect is constant and additive. Real-world relationships (e.g. diminishing returns on study hours) can be more complex.
- **Not for high-stakes decisions.** Do not use this tool to make decisions about admissions, grading, or resource allocation. It is an educational decision-support demo, and it has not been audited for fairness (for example, `parental_education` is a feature).

## 🖱️ How to Use the App (Step-by-Step)

1. **Open the app** in your browser (locally at `http://localhost:8501`, or via the deployed Hugging Face Space link).
2. **Read the sidebar.** It shows the model's evaluation scores (R², MAE, RMSE) so you can see how reliable the predictions are.
3. **Set the student's details** using the controls on the main page. Each control only allows values inside the range the model was trained on:

   | Input | Control | Allowed values |
   |---|---|---|
   | Study hours per day | Slider | 0 – 12 (steps of 0.5) |
   | Attendance percentage | Slider | 40 – 100 |
   | Previous exam score | Slider | 0 – 100 |
   | Sleep hours per night | Slider | 3 – 10 (steps of 0.5) |
   | Screen time (non-study) hours/day | Slider | 0 – 10 (steps of 0.5) |
   | Parental education level | Dropdown | High School, Bachelors, Masters, PhD |
   | Extracurricular activities | Yes / No | Radio buttons |
   | Internet access at home | Yes / No | Radio buttons |
   | Part of a study group | Yes / No | Radio buttons |
   | Receives tutoring | Yes / No | Radio buttons |

4. **Click the “🔮 Predict Final Exam Score” button.**
5. **Read the result:**
   - the **predicted final exam score** out of 100,
   - the **performance band**:

     | Predicted score | Band |
     |---|---|
     | 85 and above | Excellent |
     | 70 – 84.9 | Good |
     | 50 – 69.9 | Average |
     | Below 50 | Needs Improvement |

   - a **progress bar** showing the score visually.
6. **Experiment.** Change one input at a time (for example, raise study hours) and predict again to see how each factor moves the estimate.

> 💡 The app does not store or upload anything you enter. Every prediction is calculated live from the saved model.

## 🔄 Working Pipeline Flowchart

The pipeline has two separate phases: **training** (done once by the developer) and **serving** (runs every time someone uses the app). The app never retrains — it only loads what training saved.

```
┌──────────────────────────────────────────────────────────────────┐
│  1. RAW DATA                                                     │
│     data/student_data.csv                                        │
│     (1,000 student records: 10 inputs + final exam score)        │
└──────────────────────────────────────────────────────────────────┘
                                 │
                                 │  clean, encode, engineer features
                                 ▼
┌──────────────────────────────────────────────────────────────────┐
│  2. TRAINING SCRIPT  ->  src/train_model.py                      │
│     uses src/data_preprocessing.py                               │
│     80/20 split -> StandardScaler -> LinearRegression.fit()      │
│     evaluates on the 20% test set (R2, MAE, RMSE)                │
└──────────────────────────────────────────────────────────────────┘
                                 │
                                 │  saves everything the app will need
                                 ▼
┌──────────────────────────────────────────────────────────────────┐
│  3. SAVED ARTIFACTS  ->  models/                                 │
│     linear_regression_model.pkl   trained model (weights)        │
│     scaler.pkl                    fitted StandardScaler          │
│     feature_names.json            exact feature order            │
│     metrics.json                  R2 / MAE / RMSE                │
└──────────────────────────────────────────────────────────────────┘
                                 │
                                 │  loaded ONCE at app start-up (cached)
                                 ▼
┌──────────────────────────────────────────────────────────────────┐
│  4. APP BACKEND  ->  app.py                                      │
│     loads the four artifacts from models/                        │
│     never retrains, only predicts                                │
└──────────────────────────────────────────────────────────────────┘
                                 │
                                 │  renders the interface
                                 ▼
┌──────────────────────────────────────────────────────────────────┐
│  5. STREAMLIT UI  (in the browser)                               │
│     sliders, dropdowns, radio buttons and a Predict button       │
└──────────────────────────────────────────────────────────────────┘
                                 │
                                 │  user submits student details
                                 ▼
┌──────────────────────────────────────────────────────────────────┐
│  6. LIVE PREDICTION                                              │
│     inputs -> feature vector (order from feature_names.json)     │
│     -> scaler.transform() -> model.predict() -> clip to 0-100    │
│     -> predicted score + performance band shown to the user      │
└──────────────────────────────────────────────────────────────────┘
```

**Key idea:** steps 1–3 happen **once, offline**. Steps 4–6 happen **every time a user opens the app**. Everything the app needs is frozen inside `models/`.

## 📦 What Each Saved Artifact Does

Running `src/train_model.py` produces these files in `models/`:

| File | What it is | Used by the app for |
|---|---|---|
| `linear_regression_model.pkl` | The trained Linear Regression model (its learned weights) | Calculating the predicted score |
| `scaler.pkl` | The fitted `StandardScaler` (mean and standard deviation of each feature from training) | Scaling live inputs exactly the way the training data was scaled |
| `feature_names.json` | The exact list and order of features the model was trained on | Building the input vector in the correct order |
| `metrics.json` | R², MAE and RMSE from the held-out test set | Showing model quality in the sidebar |

`models/feature_importance.csv` may also be present; it is a reference table of standardized coefficients and is not loaded by the app.

**The features the model expects (in this order):**
`study_hours_per_day`, `attendance_percentage`, `previous_exam_score`, `sleep_hours`, `screen_time_hours`, `parental_education_score`, `extracurricular_activities_encoded`, `internet_access_encoded`, `study_group_encoded`, `tutoring_encoded`, `engagement_index`

`engagement_index` is an engineered feature the app calculates itself from study hours, attendance, and screen time.

## 💻 Run It Locally

**Prerequisites:** Python 3.10 or newer.

```bash
# 1. Get the code
git clone https://github.com/datascienceds005-ML/student-ml-website.git
cd student-ml-website

# 2. Create and activate a virtual environment
python -m venv venv
venv\Scripts\Activate.ps1          # Windows PowerShell
# source venv/bin/activate         # macOS / Linux

# 3. Install dependencies
pip install -r requirements.txt

# 4. Launch the app (trained model files are already included in models/)
streamlit run app.py
```

Then open **http://localhost:8501**.

> **Windows PowerShell tip:** if activation is blocked, run `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` once, then activate again.

Optional developer commands (run from the **project root**):

```bash
python data/generate_dataset.py     # regenerate the synthetic dataset
python src/eda.py                   # regenerate EDA charts into assets/
python src/train_model.py           # retrain the model and refresh models/
```

## 🔁 Using a New Dataset (Retraining Guide)

The model is tied to the dataset it was trained on. To use a brand-new dataset, a developer must **retrain**. The steps depend on whether the new data has the **same columns** as the current one.

### Case A — Same columns, different values (the simple case)

1. **Replace the CSV.** Put your new file at `data/student_data.csv`, keeping the same column names and types as the current file.
2. **Retrain.** From the project root, run:
   ```bash
   python src/train_model.py
   ```
   This automatically re-splits the data, refits the scaler and model, re-evaluates, and **overwrites** `linear_regression_model.pkl`, `scaler.pkl`, `feature_names.json`, and `metrics.json` in `models/`. You do not edit those files by hand.
3. **Restart the app.**
   ```bash
   streamlit run app.py
   ```
   The sidebar will now show the new metrics, and predictions will come from the new model.
4. **Redeploy (if hosted).** Commit the updated `models/` files and push them, then rebuild the Space — a deployed app only sees the artifacts that are committed to the repository.

### Case B — Different columns or a different target

Retraining alone is **not enough**, because the preprocessing code and the app's input form are written for the current columns. In addition to steps 1–4 above, you must:

1. **Update `src/data_preprocessing.py`** — the lists of numeric and categorical features, the target column name, any encoding maps, and the feature list used to build the training matrix.
2. **Update `app.py`** — the input widgets (sliders, dropdowns, radio buttons), their allowed ranges, and the function that turns the user's inputs into the feature vector.
3. Retrain, restart, and test that a prediction works end to end.

> ⚠️ Always check that the widget ranges in `app.py` match the value ranges in your new data. If a slider allows values the model never saw during training, the prediction will be unreliable.

## 📊 Model Performance

Evaluated on a held-out test set of 200 students (the model was trained on the other 800):

| Metric | Value | Meaning |
|---|---|---|
| **R² Score** | ~0.74 | The model explains about 74% of the variation in final scores |
| **MAE** | ~4.7 points | Predictions are typically within 5 points of the actual score |
| **RMSE** | ~6.0 points | Typical error, with larger misses weighted more heavily |

Exact values are stored in `models/metrics.json` and shown in the app's sidebar. Remember these figures come from **synthetic** data — see [Limitations](#-important-limitations--please-read).

## 🚀 Deployment

This project is deployed as a **Docker Space on Hugging Face**. The YAML block at the very top of this README (`sdk: docker`, `app_port: 8501`) tells Hugging Face how to run it — **do not remove it** if you push this repository to a Space.

The `Dockerfile` installs the dependencies from `requirements.txt`, copies the project, and starts Streamlit on port 8501.

To run the same container locally:

```bash
docker build -t student-performance-app .
docker run -p 8501:8501 student-performance-app
```
